# وحدة العملاء — استعادة العمل وتسليم المراجعة

الفرع: `feature/customer-management`. الأساس المحفوظ: `feature/banking-finance-workbench` عند `ad6d54a54e527fc1b96a0a51ea7f9438181a9d13` (PR #13). لم تدمج أعمال #10–#13، ولم يفترض أن النسخة المنشورة تحتويها.

## الاستعادة وحفظ العمل

استُعيدت ملفات الواجهات وAPI وقواعد العملاء وقارئ Excel والترحيل المقترح والاختبارات من مساحة العمل نفسها، دون إعادة برمجة من الصفر. التعديل `28a3c98` نقطة حفظ للعمل المسترجع قبل استكمال التحقق. محاولة كتابة اختبار XLSX إضافي والاختبار المالي الأخيرة قبل انقطاع البيئة لم تكن محفوظة؛ أضيفت هذه الاختبارات فقط بعد التحقق من الملفات المتاحة.

## المنفذ فعلياً

- سجل عملاء مركزي، أرقام ثابتة وتصاعدية رقمياً، بحث بالاسم/جزء بداية كلمة والرقم والهاتف والمعرفات، فلاتر الشركة والنوع والحالة والفترة ورقم الملف، تحميل تدريجي، إظهار الأعمدة وترتيبها، وتفضيلات مستخدم محفوظة مشفرة على الخادم.
- ملف عميل وإنشاء وتعديل ونقل بين الشركات النشطة مع سبب وتاريخ وتدقيق. النقل يغير الشركة الحالية فقط؛ لا يعيد إسناد الحركات البنكية أو الأحداث أو المستندات التاريخية. إيقاف الملف مستقل عن نوعه، وطلب الخدمة لغير النشط يتطلب استثناءً مخولاً موثقاً.
- الحد الأدنى للاسم والشركة، وثلاثة أنواع وخمس حالات مستقلة، وبيانات الجنسية والميلاد والكفيل وجهة الإقامة، وأرقام تواصل متعددة وحالة كل رقم ورقم رئيسي وWhatsApp وموافقة تسويق موثقة لكل رقم. لا إرسال تسويق أو تكامل خارجي مفعّل.
- السكن الحالي مرتبط بمرجع المناطق القائم، والعناوين السابقة محفوظة في سجل التغيير وتظهر في الملف. جهات طوارئ متعددة بأساس جمع مشروع، دون استحقاق مالي أو موافقة تسويق مفترضة.
- ملفات مشفرة في مخزن الكائنات الخاص الحالي، وبيانات وصفية مشفرة وروابط وإصدارات مستقلة. فحص الأنواع والتوقيعات والحجم، ومنع التنزيل قبل نجاح الفحص. عامل الفحص الحالي يدعم ملفات العملاء بدور الخدمة المقيد الموجود، دون تخفيف حماية RLS أو تغيير منح المستخدمين.
- زيارات مشتركة وعلاقات متبادلة بنطاق الاطلاع وأساس حفظ ودرجة تحقق واضحة، دون تعقب مواقع. الحاضر يُسجل بملف مستقل عندما يكون جمع بياناته مشروعاً.
- ملاحظات واتفاقات وتعهدات وسجل زمني، وسجل تدقيق مستقل مشفر قبل/بعد لا يعدله المستخدم العادي. تنبيهات الملف الناقص وانتهاء الوثائق والتحقق من العنوان تظهر داخل الملف.
- سجل تعهدات بإصدارات وأفعال إصدار/تعديل/إلغاء/استكمال مستقلة، ومصمم حقول دون تعديل الكود. الاستكمال يحتاج ملفاً موقعاً من الفئة الصحيحة، وفحصاً ناجحاً وتوثيق تحقق؛ لا يكفي الضغط على زر أو رفع ملف محجور.
- نتائج الاتصال الأربع المعتمدة، وإعادة تنبيه 30/60 دقيقة افتراضياً، وحفظ تاريخ المواعيد، وإعداد المدد للمخول. يستخدم مخزن الإشعارات المركزي الموجود في 009 ولا ينشئ مخزن إشعارات موازياً؛ القراءة تتحقق من نطاق المستلم وتتجاهل تذكير اتصال تجاوزه اتصال أحدث.
- وقائع تعاون موثقة ومصادر تقييم ومراجعات تاريخية بالأوزان 60/15/15/10، دون إدخال درجة مباشرة أو تكرار مصدر الواقعة. تظل النتيجة **غير مصنف** عند غياب مصادر السداد أو نتائج المواعيد المكتملة؛ لا عقوبة أو وزن بديل لنقص البيانات. وقائع الموظف والتوقيت والاستكمال محفوظة، دون نقاط تقييم موظفين نهائية.
- مسودات آلية مشفرة على الخادم، استعادة بعد تحديث المتصفح، عزلها بالمستخدم والشركة، دون تخصيص رقم عميل قبل الحفظ النهائي. المسودة لا تدخل عدد العملاء.
- استيراد وهمي قابل للاستكمال بواقع 25 صفاً في الدفعة، CSV وXLSX للورقة الأولى، حفظ الرقم القديم والملاحظات والحقول الأصلية داخل بيانات تاريخية مشفرة، تقرير استثناءات ومنع تكرار المحاولة، واستمرار الترقيم بعد الأرقام المستوردة. قارئ XLSX بإصدار مثبت وقيود للحجم والتوسع المضغوط والوقت والذاكرة، ورفض الماكرو والكيانات الخارجية.
- عرض الحركات البنكية المعتمدة المرتبطة بالعميل فعلياً، مع مدين/دائن ورصيد وافتتاحية الفترة منفصلة لكل شركة وعملة، CSV وExcel XML وطباعة المتصفح/حفظ PDF وفق التفويض. ليس هذا كشف مستحقات أو قوائم مالية مكتملة.
- واجهات عربية/إنجليزية RTL/LTR، وأحجام الكمبيوتر والتابلت والهاتف، والوضعان الفاتح والداكن مع التصميم والشعار القائمين. لا حفظ بيانات عميل أو وثائق في localStorage.

## قاعدة البيانات والأمان

`supabase/proposed/010_customers.sql`: عشرة جداول (`customers`, `customer_numbers`, `customer_drafts`, `customer_events`, `customer_visits`, `customer_visit_people`, `customer_files`, `customer_file_reviews`, `customer_templates`, `customer_imports`) مع مفاتيح مستقلة وعلاقات مركبة للمجموعة، وفهارس الترقيم والبحث، وRLS، وتاريخ ملفات/تعهدات/أحداث غير قابل للتعديل من مستخدم التشغيل. إضافة موعد استحقاق إلى مخزن الإشعارات الحالي. لا حذف بيانات أو جداول، ولا استبدال علاقات الوثائق القائمة. كتالوج أفعال العملاء مضاف للمراجعة فقط، ولا تمنح صلاحيات جديدة لأي مستخدم أو دور قائم تلقائياً. يظل فحص الشركة والإجراء على الخادم إلى جانب عزل RLS للمجموعة.

الترحيلات الثمانية المعتمدة وmanifest اعتمادها لم تتغير. إعدادات Render وSupabase والأسرار وحساب تجربة الدخول لم تتغير. لم تنفذ اختبارات أو كتابة على Supabase؛ كل قواعد الاختبار الجديدة محلية مستقلة وببيانات وهمية، مع الحفاظ على القواعد والملفات السابقة.

## التحقق والتسليم

يشمل الاختبار الإنشاء وإعادة القراءة والتحرير والتعارض والتشفير والأرقام الثابتة، ونقل عميل مع حركة بنكية معتمدة وبقائها للشركة الأصلية، ومنع الطلب غير المخول، وعزل المسودات وRLS، والوثائق والإصدارات والحجر وعامل الفحص والتعهدات والعلاقات والاتصالات والتكرار والاستيراد القابل للاستكمال. اختبار أداء محلي لـ1500 سجل مشفر مع طلب API حقيقي للصفحة الأخيرة؛ ليس ضمان أداء إنتاجياً.

اختبارات المتصفح تشمل المسودة ثم تحديث الصفحة، إنشاء الملف وأرقام الاتصال والعنوان، رفع مستند واستكمال تعهد، مكالمة وملاحظة، النقل والبحث والمالية الفارغة، واللغتين وأحجام 1440/1024/768/390 والوضعين، دون أخطاء JavaScript أو كتابة حساسة في تخزين المتصفح. يعمل نفس الاختبار على غياب 010 لإثبات عدم ادعاء الحفظ. CI لا يحتوي بيئة Supabase أو أسراراً أو خطوات نشر، ويعيد فحوص الشركات والبنوك والمستخدمين والمالية السابقة ونسخ PostgreSQL الاحتياطية واستعادتها وصورة التشغيل.

## الخطوة التالية

مراجعة PR العملاء وحدوده و010، ثم موافقة صريحة منفصلة قبل تطبيق الترحيلات أو منح تفويضات أو تحديث رابط Render. لا يلزم إنشاء Supabase أو إعادة تنزيل نظام أو إدخال أسرار في هذه المرحلة.

نتائج الاختبارات عند التسليم: **68 اختبار Backend ناجح، و111 اختبار قواعد/وظائف ناجح، وصفر فشل**. تشمل الـ68 اختبارَي XLSX، وثمانية سيناريوهات تكامل للعملاء، وانحدارات النظام السابقة. بناء JavaScript والتحقق من مصدر الحزمة وactionlint ناجحة. اختبار المتصفح مع المخطط المقترح ناجح؛ فحص CI المرفق بطلب المراجعة يعيد التحقق من حالتي وجود/غياب المخطط وبناء صورة التشغيل دون نشر أو أسرار.
