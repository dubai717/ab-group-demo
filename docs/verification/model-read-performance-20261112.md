# AB Group — تقليل رحلات قاعدة البيانات للنموذج المشترك

فوق الإصلاح العادي PR #74 فقط. لا ترحيل، ولا تبديل صلاحيات أو معادلات أو أرصدة أو مخطط. البيانات المقروءة والتحويلات كما هي؛ جُمعت SELECTs السبع الثابتة للنموذج في حزمة PostgreSQL واحدة على اتصال ومعاملة الطلب نفسيهما. لا إدخال مستخدم في SQL، ولا اتصال موازٍ، ولا ذاكرة مشتركة بين الطلبات أو المستخدمين. نجاح جميع النتائج لازم؛ فشل أي statement يرفض النموذج كاملاً ولا يعاد كأصفار.

نقيس عدد استدعاءات client.query، أي رحلات الاتصال، وليس عدد statements الداخلية أو كلفة خطة PostgreSQL. عدد SELECTs الأساسية لم يتغير؛ الذي انخفض هو انتظار الاتصال المتتابع. تبقى حدود RLS والبيانات المشفرة في التخزين والترشيح الأصلي في خدمات السجلات كما هي.

المصدر نفسه `backend/tests/dashboard-performance.mts`: 100 مستثمر اصطناعي، 12 بنكاً في شركتين، 8 ملفات PDF خاصة فعلية، 7 عينات محلية دافئة. لا شبكة Render أو Supabase خارجية في القياس.

مقارنةً بـPR #74 وحده: اللوحة 42→36، وبقية الشاشات تنخفض ست رحلات لكل نموذج. بعض وسائط الزمن لم تتحسن، ولا نستنتج تحسناً شاملاً للزمن أو ضماناً لسرعة الإنترنت من سبع عينات محلية. التحسن الحتمي القابل للفحص هو خفض رحلات القراءة مع بقاء البيانات والدقة والنطاق.

اختبار PostgreSQL فعلي يتناوب بين المالك والموظف، ثم يمنح عرض بنك لشركة واحدة ويقرأ البنك الصحيح، ويعيد قراءة المالك، ويسحب المنحة ويثبت زوال وصول الموظف فوراً. اختبار View As الأصلي يثبت بقاء المعاملة للقراءة فقط وهوية المالك وسجل التدقيق. خطأ SQL داخل الحزمة يرفض القراءة كاملة، وتعمل القراءة الجديدة بعد rollback دون نتائج جزئية أو ذاكرة قديمة.

ترجمة أسماء صلاحيات الأدوار الأساسية تعديل عرض فقط؛ لا تغير محتوى الأدوار أو المنح. تبقى PR #72 و#73 و028 ومقترح #61 خارج هذا النشر.
