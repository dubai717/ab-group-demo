# Personnel reference directory and original document links

Repository: dubai717/ab-group-demo only. Base staging release: 1e599f5 (PR83; protected delivery43514827305 completed successfully).

## Implementation

- Existing departments remain the only unit records. Seven default bilingual type definitions (ADM/COL/FIN/HR/PRO/OPS/BD) are read without seeding data. Owner-confirmed custom type additions are serialized, duplicate checked, append-only settings entries. The new unit editor selects a type; the server derives names/code, prevents manual tampering, and preserves legacy records without forcing a new code or reinterpreting their scope. No role/grant/membership changes are triggered.
- Group scope is explicit descriptive metadata in the existing department profile. The existing non-null company foreign key is retained as its immutable compatibility anchor; no schema alteration or company membership is fabricated. Group units are eligible in staff forms for authorized HR operators of other companies, while employment company, financial responsibility and all existing security scopes stay unchanged. Company-specific and group definitions have separate duplicate checks. Unit responsibility selects a real eligible employee and does not invent a job or login.
- Employee profiles retain primary identity/contact/employment data. Work-company coverage is descriptive metadata, validated against existing HR rights; it does not insert financial/job assignments, security memberships or grants. Restricted passport/residency/work-permit fields remain encrypted. Linked login editors show account/security fields and link back to the employee; server guards reject parallel changes to employee-owned fields. The existing explicit one-time account link and original credential procedures are reused. Owner and nonemployee users retain their existing editor.
- Multiple documents use original encrypted durable storage, scanning, versions, idempotency and HR document rights. Academic/professional/course/experience categories, issue/expiry dates and notes are supported. Concurrent duplicate content is rejected for accidental new uploads; explicit new versions retain their lineage. Lazy image/PDF thumbnails use the existing viewer with at most two decoders; full view/download rechecks original server authorization.
- Personal files of a correctly linked existing login appear through a read-through logical link in the employee document section. Original document ownership, bytes, IDs, metadata, version chains and evidence links are not moved, copied, deleted or rewritten. Both the employee-document permission and original user-attachment permission are required. Clean scan and checksum are checked before bytes are returned, with an audit event. Unlinked accounts are left alone. Linked-user screens point to Personnel instead of displaying a second personal document editor. This is not a bulk migration; none is performed or required for this code release.
- A shared country selector enhances telephone fields across existing modules. UAE/Saudi/Indian and other explicitly selected national formats normalize to international + notation; other countries can always be entered internationally. Unknown local legacy values are retained without guessing a country. New edited national input requires an explicit country. International normalization also runs server-side on contact fields, including customer phone arrays, without rewriting existing stored rows. Merely having a phone does not imply WhatsApp enrollment. Authorized staff profile views offer tel links and a WhatsApp link only for the separately supplied WhatsApp value.

## Safety and delivery

No migration, financial028, bulk document migration, balance edit, secret change, account enrollment by linking, permission reset, branch table or production deployment. The original legacy department API remains compatible; all new daily HR unit creation uses the reference selector. Source integrity manifest includes the new phone module.

Local focused integrations and actual Personnel browser journeys pass; final full-server, exact-head and merged-push checks must pass before protected staging delivery. Tests create only isolated random synthetic databases and use fake providers. Real user documents are not sampled or moved during tests. The final release report records native results and exact live version. Add attachment-viewer.js to the existing fixed-origin GET-only source-byte smoke list on main; keep all trusted controller pins, environment gates and schema catalog unchanged.

Rollback: no database restoration is needed for this code release. Keep original documents, settings, new HR records and historical references; use a compatible code fix if later staff records rely on group metadata. Never restore a database over subsequent financial activity.
