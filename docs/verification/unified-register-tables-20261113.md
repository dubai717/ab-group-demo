# Unified AB register tables

Repository: dubai717/ab-group-demo. Based on tested staging aef693f. No schema migration, permission assignment, balance change or financial 028 activation.

The shared stylesheet covers all native record tables, including floating profiles and nested details: existing primary/line/panel/gold palette, white dark-header text, alternating rows, hover/selection, thin cell boundaries, readable widths, sticky heads and contained horizontal/vertical scrolling. Original semantic status colours and original action buttons remain. Long values receive plain-text tooltips. Existing open/profile/original-record actions gain keyboard/row activation where the row has no existing native activation. No action is invented for rows without an explicit open control; financial approve/pay/etc. actions are never invoked by row selection.

Existing RegisterTools/Store/View and FinancialTables are retained. Column filters, compound conditions, global search and server authorization are reused. New controls show exact filtered totals, clear all filters, and paginate complete profile/user/personnel/document/approval snapshots at 50 rows. Filtering precedes pagination. Exports still request the entire filtered authorized source; personnel profile navigation retains all filtered IDs. Default source order remains unchanged until an explicit sort. Profile snapshot tables bind locally even when their caller has no redraw hook; original row nodes/handlers are retained across paging/filtering, avoiding form redraw and broken action bindings. Filter popups stay inside native modal top layers and Escape closes the filter without cancelling the file.

Company, bank, customer and vehicle main registers retain existing server pagination. Large financial filter responses now use validated 200-row server pages instead of retransmitting the whole filtered source. This does not claim a new streaming implementation for every legacy workbench: existing authorized workbench snapshots are still supplied by their original providers; this UI change adds no new bulk database/browser source loading. A future replacement of those providers must preserve their joined financial/source validation.

A new browser journey (invoked by that existing CI suite) passed for 257 full-source rows: decimal sort, multiple filters, reset/paging, original-record keyboard opening, Arabic/English desktop/tablet/phone, sticky headings and brand contrast. Full local backend tests passed 348/348; full source-specific CI is required before merge/publication.
