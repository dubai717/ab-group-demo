- قائمة المستخدمين والبحث والتصفية، بيانات الملف العربية/الإنجليزية والهوية والجنسية والتواصل والوظيفة وتاريخ التعيين والمسؤول والشركات والإدارات، تفعيل/إيقاف، حماية المالك، التفويضات وحدودها وإعادة التفويض الصريحة والمرفقات الشخصية وسجل الجلسة.
- الإمارات السبع والبحث في المناطق التابعة للإمارة، مرجع مشترك 367 مدخلاً بمصادرها، إضافة مخولة مع منع التكرار واختيار تلقائي والمستخدم والوقت، دون تغيير المواقع السابقة.
- إنشاء الشركات والسجل وفتح الملف وتحريره، الحفظ والتحقق بالقراءة بعد الكتابة وإعادة الفتح، حقلا سالك والرمز المروري مرة واحدة، الوثائق الثلاث الاختيارية ومعايناتها والتواريخ، تقرير الوثائق والرموز وتنبيهات 60/30/7 ومددها القابلة للتعديل.
- حسابات بنكية متعددة للشركة، الحقول المطلوبة والمراجع القابلة للتوسعة، معرّفات مستقلة، إنشاء/عرض/تعديل/إغلاق وحفظ وفلاتر ومنع التكرار، إبقاء الحساب المغلق، وسجل تغييرات محلي.
- قسم مستندات البنك: أنواع مسموحة وتصنيف وعنوان ووصف وتاريخ، عدة ملفات وروابط للعقد/السابق وإصدارات متتابعة وعرض وتنزيل دون استبدال القديم تلقائياً.
- بيانات مدير الحساب الاختيارية لكل حساب: الاسم والهاتف الدولي والبريد، الحفظ والتعديل والتدقيق بنفس صلاحيات الحساب.
- الاستعادة بالوسائل الثلاث وإرشاد المسؤول، والقائمة الشخصية وإعدادات تغيير كلمة المرور، مع حدود صريحة تمنع إرسالاً أو تحققاً أو نجاحاً وهمياً.

## معالجة إنشاء المستخدمين وبيانات الدخول

واجهة المستخدم الحديثة باقية بكامل حقولها. أُعيدت القدرة التجريبية على إنشاء بيانات دخول دون الرجوع إلى نموذج كلمات المرور المكشوفة القديم:

1. خيار اختياري صريح **إنشاء دخول تجريبي محفوظ في هذا المتصفح** عند إنشاء مستخدم. دون تفعيله يبقى تدفق الملف المؤقت كما في #4، ولا يدّعي أنه حساب دخول.
2. الحقول الجديدة لكلمة مرور وهمية وتأكيدها. السياسة 12–128 حرفاً تشمل كبيراً وصغيراً ورقماً ورمزاً دون مسافات. لا تُولد كلمة مرور أو تُرسل، ولا تُسجل في التدقيق.
3. `demo-credentials.js` يستخدم Web Crypto: PBKDF2-SHA256، عدد دورات 600,000، ملح عشوائي مستقل 128 bit ومشتق 256 bit. يُحفظ المشتق وبياناته فقط، لا كلمة المرور. غياب Web Crypto يعطي فشلاً واضحاً دون إنشاء حساب جزئي.
4. المفتاح المنفصل `ab_group_demo_accounts_v1` يحفظ دليلاً محدوداً: ID/username وأسماء العرض وبيانات التواصل والوظيفة وتاريخ التعيين والارتباطات والدور والحالة، مع verifier. **لا هوية إماراتية ولا جنسية ولا ملفات ولا تفويضات ولا سجل مستخدمين ولا كلمة مرور مكشوفة** في هذا الدليل. استخدم بيانات وهمية؛ بيانات الدليل ليست مشفرة.
5. الحساب المحلي النشط يستطيع الدخول في المتصفح والأصل نفسيهما وبعد التحديث. تعديل اسمه/حالته ودليل ارتباطاته عبر المستخدم المخوّل يُحفظ لهذا الدليل. التحقق من الحقول والتفويض يتم قبل اعتماد الحفظ؛ فشل الكتابة أو القراءة اللاحقة لا يعتمد الملف أو حالته ولا يترك مرفقات/تدقيقاً جزئياً، وتبقى مدخلات النموذج.
6. المستخدمون الجدد يبدأون بدور الموظف. المالك وحده يمكنه اختيار دور موجود غير المالك عند الإنشاء؛ لا تصعيد بواسطة مفوض محدود ولا إنشاء مالك ثانٍ. لا تتغير أدوار المستخدمين الحاليين عبر حمولة الملف.
7. الحسابات القديمة وكلمات مرورها تبقى في مصدرها دون ترحيل أو استبدال. تعديل اسم ملف حساب قديم يبقى للجلسة ولا يغير اسم دخوله؛ يظهر ذلك صراحةً في ملفه. تغيير بيانات الدخول القديمة يحتاج انتقال مصادقة معتمداً، ولا يُنفّذ هنا بصمت.
8. `currentUser` الجديد يُحفظ كمعرّف فقط، ثم يُقرأ من الدليل الفعّال؛ لا تُنسخ الهوية أو كلمة مرور جديدة إلى حالة الجلسة المحفوظة. تستمر قراءة اختيار المستخدم القديم المتوافق مع v2/v3 عبر معرّفه.
9. لا إعادة تعيين كلمة مرور عبر هذا الدليل، ولا تفعيل لميزة change/forgot-password الآمنة. يبقى التحقق من الحالية والتغيير والاستعادة والإشعارات محجوباً لغياب الخادم، حتى للحساب التجريبي المحلي.

هذا **ليس مصادقة آمنة أو دائمة أو مشتركة**: المتصفح والمستخدم المحلي يستطيعان تعديل الأدوار والمشتقات والهوية المختارة؛ يمكن مهاجمة verifier دون اتصال. اختيار الجلسة قديم وتجريبي، ولا توجد جلسة HttpOnly أو تحقق خادمي أو حماية ضد XSS أو rate limits أو مزامنة إيقاف بين الأجهزة/التبويبات. مسح التخزين يفقد الدليل. لا تستخدم كلمات مرور أو بيانات أشخاص حقيقية. المصادقة القديمة ما زالت تتضمن بيانات دخول تجريبية مكشوفة؛ لم تُقدَّم كآمنة ولم تُغيَّر دون إذن.

## توحيد المستخدم والصلاحيات بين الوحدات

- `getCanonicalActor()` يقرأ المستخدم الفعّال من خدمة إدارة المستخدمين، بدلاً من بحث منفصل في `app.state.users` كان يُسقط المستخدمين الجدد وتغييرات الجلسة. الشركات والمناطق والبنوك تستخدمه، مع الأدوار الأصلية بلا تعديل.
- تفويضات البنك في شاشة المستخدمين مستقلة: `bank_view`, `bank_create`, `bank_edit`, `bank_close`, `bank_view_documents`, `bank_manage_documents`، بنطاق مجموعة أو شركة فقط. يعاد تطبيقها كصلاحيات لكل شركة في خدمة البنوك. الأدوار المالية العامة لا تكسبها تلقائياً.
- التفويض المحدود لا يمنح حقاً أوسع أو حقاً لا يملكه، ولا يعيد التفويض دون الصلاحية الصريحة. التفويضات السابقة من نوع `companyBankPermissions` تُحترم؛ لا تُعدل أو تُسحب تلقائياً.
- تفويضات البنك وحدها لا توسع الاطلاع على الملفات الشخصية. أُضيف اختبار يمنع تسرب الملف بسبب إضافة أفعال البنك إلى سجل صلاحيات المستخدمين.
- التفويضات الجديدة تبقى للجلسة وتزول بالتحديث، بخلاف دليل الدخول المحلي. لا تُعرض كصلاحيات مركزية دائمة.
- أزرار تغيير حالة الشركة ومعالجها يعيدان فحص `edit_company`/المالك القائمين؛ لا تتيح واجهة العرض فقط تغيير الحالة.
- أعداد لوحة التحكم تستخدم سجل المستخدمين الموحّد فتحتفظ بمعنى العدّ الإجمالي وتضم المستخدمين الجدد، دون كشف ملفاتهم لمن لا يملك حق الاطلاع.

## متطلبات Backend قبل الاستخدام الحقيقي

1. قاعدة بيانات للمستخدمين والشركات والعضويات والمسؤولين والتفويضات والحسابات والمراجع، بمفاتيح وعلاقات وقواعد فريدة ومعاملات وتزامن، وهجرة reviewed لا تحذف السجلات الأصلية.
2. مصادقة موثوقة (Argon2id/server-side password hashing، جلسات HttpOnly/Secure، CSRF، rate limiting، إبطال الجلسات والتوثيق). لا تُستورد كلمات المرور التجريبية إلى الإنتاج؛ خطة enrollment/reset للمالك والمدير العام والمستخدمين مع مراجعة قبل التحويل.
3. قنوات اتصال موثقة وخدمات إرسال SMS والبريد وWhatsApp، تحديات أحادية الاستخدام بمدة صلاحية وحد محاولات وحماية من إعادة الاستخدام وإشعارات بعد تغيير حقيقي، مع استعادة إدارية مصرح بها وحماية المالك.
4. تخزين ملفات خاص مشفر، تحكم وصول عند كل رفع/قراءة/تنزيل، فحص محتوى وملفات مكتبية وبرمجيات ضارة، روابط قصيرة العمر، إصدارات غير قابلة للاستبدال وربط بالعقود، وretention/backup/recovery.
5. مصدر صلاحيات موحد وخادمي وسجل تدقيق دائم محمي من التلاعب، لا يعتمد على `localStorage` أو حقول العميل.
6. مرجع مركزي للمناطق والبنوك والأغراض، مراجعة المصادر الرسمية وتحديثاتها، scheduler للتنبيهات، وخدمات التقارير عند اعتماد نطاقها. التقارير العامة/المالية/الجغرافية الشاملة لم تُنفذ بمجرد توحيد هذا الفرع.

خطة انتقال المصادقة التفصيلية في `AUTHENTICATION-TRANSITION.md` باقية. لا يُفعّل التحويل الجوهري أو الهجرة الإنتاجية أو النشر دون مراجعة وموافقة منفصلة.

## الاختبارات

حزمة اختبارات المنطق/التخزين: 101 اختباراً في ثمانية ملفات، تشمل اختبارات الفروع السابقة + 8 اختبارات للدليل التجريبي + توسيع اختبار المستخدمين إلى 23 حالة. تُشغّل كل حزمة بـ `node tests/<name>.test.cjs`.

اختبارات Playwright الثمانية:

- `area-reference.browser.cjs`: البحث والإضافة والتكرار والصلاحيات ونطاق المتصفح وحماية المواقع.
- `company-documents.browser.cjs`: الوثائق والتواريخ والرموز والتقرير والتنبيهات والصلاحيات والبيانات السابقة.
- `company-profile-save.browser.cjs`: إنشاء وفتح وتحرير وحفظ وإعادة تحميل ومحاكاة فشل حفظ.
- `bank-accounts.browser.cjs`: حسابات متعددة وحالة وإغلاق ومنع تكرار ومستندات وعلاقات وإصدارات وعرض وتنزيل وبيانات المدير.
- `user-management.browser.cjs`: المستخدمون والتعيينات والمرفقات والتفويضات وحماية المالك والقراءة فقط وحدود تخزين الجلسة.
- `auth-flows.browser.cjs`: الدخول الصحيح والخاطئ والخطأ العام، القنوات الثلاث، منع التحقق الوهمي، الإعدادات الشخصية للمالك والمدير العام والموظف والتابلت والهاتف.
- `integration.browser.cjs`: شركة ← بنك ومدير ← مستخدم ودخول محلي اختياري ← فشل صيغة/تخزين دون ملف جزئي ← تفويض البنك من الواجهة ← دخول وإجراءات بنك ومستندات ← منع ربط شركة غير مصرح بها ← إعدادات كلمة المرور المحجوبة ← إيقاف/إعادة تفعيل وتعديل اسم الدخول وإعادة تحميل؛ تحقق من عدم حفظ كلمات المرور والهوية والجنسية والملفات، ومن عدم تغير المستخدمين والأدوار القديمة.
- `legacy-regression.browser.cjs`: الشعار والتصميم واللغتان والتنقل والمستخدمون والشركات والرفع العام والفلاتر والحالة والحفظ والمهام والأدوار والخروج وv2 وأولوية v3 والبيانات التالفة ومنع تغيير حالة الشركة للقراءة فقط.

لتشغيل المتصفح: شغّل `npm start` محلياً، ثم `ERP_DEMO_URL=http://127.0.0.1:3000 CHROMIUM_PATH=/usr/bin/chromium node tests/<name>.browser.cjs` (عدّل مسار Chromium بحسب جهازك). المخرجات داخل `work/` مستثناة من Git. لا تحاكي الاختبارات خادماً غير موجود ولا تثبت نشر البرنامج.

## قرار المراجعة

طلب التكامل للمراجعة فقط. لا دمج في `main` ولا نشر. الفروع والطلبات #3–#9 محفوظة كما هي. البنود التي تحتاج Backend أو حفظاً مركزياً أو تدقيقاً دائماً غير مكتملة للإنتاج، حتى مع نجاح الاختبارات المحلية.

### نتائج التشغيل النهائية

- نجحت الاختبارات الـ101 جميعها (المناطق 14، المصادقة 11، البنوك 15، وثائق الشركات 14، حفظ الشركة 6، دليل الدخول التجريبي 8، التخزين 10، المستخدمون 23).
- نجحت حزم Chromium الثماني المذكورة أعلاه، دون أخطاء JavaScript page errors؛ تشمل العربية/الإنجليزية و1440/768/390 بكسل بحسب التدفق.
- نجح `node --check` لجميع ملفات JavaScript الرئيسية و`git diff --check`، ولا توجد علامات تعارض متبقية أو ملفات unmerged.
- فحص Git يثبت أن رؤوس #3–#9 كلها أسلاف لفرع التكامل، وأن `assets` و`server.js` لم يتغيرا عن main. فحوص التخزين/المتصفح تثبت بقاء بيانات v2 وأولوية v3 وعدم تغيير بيانات وأدوار المستخدمين الأصليين.
- حُدّث محدد شاشة المستخدمين في اختبار المصادقة ليتحقق من الشاشة الحديثة، واستُخدم سجل شركة قديم البنية في اختبار الرجوع. لا يُعاد النموذج القديم على حساب الحقول الحديثة لإرضاء محدد اختبار سابق.
- نجاح الاختبارات لا يثبت أمناً إنتاجياً أو حفظاً مركزياً أو نشر التغييرات. لا يمكن اختبار إرسال/انتهاء OTP أو تغيير آمن فعلي أو حفظ ملفات مركزي قبل تنفيذ خدماتها.
