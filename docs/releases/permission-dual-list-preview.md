# Daily permission planning and employee preview

Baseline staging: f3f9a23. This ordinary release is the independent UI part of the owner's combined monthly-investor-settlement task; financial settlement implementation and approval remain separate work.

- Available/granted panels group full translated permission names, with independent search, scroll areas and multi-selection. Arrow buttons change local sets only. Existing owner permission-plan/permission-apply routes still validate role, scope, grant version, revision, explicit confirmation and audit. No new permission system, role mutation or grant seeding.
- Inherited role permissions are locked and distinguished from direct grants. Other-scope grants are retained. Scope selection uses existing company/current-primary-licence and department semantics; it does not invent independent secondary-licence or emirate bounds. No user's access changes on opening, moving, filtering, cancelling or selecting a scope.
- Employee/role/department filters show selected employee, department and company. Existing role templates are read-only because current server capabilities explicitly disable template/role changes; no department-template inheritance is fabricated. Choosing a role or department filters employees for their direct-grant plan. Template-edit activation would require a separately authorized existing-server procedure.
- Technical delegation/reset controls and existing company overrides are in advanced profile settings. Daily save opens a clear plan summary before confirmation. Failed committed readback retries the result without repeating grants. Unsaved changes guard target/scope/navigation switches. Owner/self escalation stays server-denied and read-only in the UI.
- The 44px native select previously retained the generic input's 14px top/bottom padding, leaving only 14px for its 16px text. A 46px accessible combobox now provides a real content area, full-name/detail options, bounded internal scrolling, search, keyboard navigation, RTL/LTR alignment and selected-name detail text. Long header identities no longer squeeze the language switch.
- `Failed to fetch` is a browser/network error rather than evidence of denied permissions. The historical browser/network incident cannot be proven without its network trace. Reproduced failure paths were unhandled uncertain preview activation and failed bootstrap readback: generic messages/recovery could lose context or clear the visible actor. Start now verifies the real owner's session-bound control state after an uncertain response, without replaying the start request. Failed bootstrap shows a read-only recovery panel with manual retry/return and preserves the login session. `previewUncertain` blocks frontend writes until successful server readback; projected server read-only transactions remain authoritative. No password use, session swap, permission relaxation or automatic network retry loop.

Tests exercise network abort, confirmed start followed by failed bootstrap, owner session preservation, frontend/server write denial, user switch, disabled inactive users, long Arabic/English names, staging multiple permissions without writes, cancellation, explicit apply/readback retry, inherited locks, revocation, owner/self protection and responsive 1440/768/390 views. No SQL migration or hosted financial fixtures are part of this release.
