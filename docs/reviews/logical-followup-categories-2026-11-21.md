# Logical Salik/traffic follow-up categories — build only

The original fee engine, item directory, future-effective rule history, approved activation, native invoice sources and worker are reused. New logical vehicle-category rules explicitly name `salik` or `traffic` and a reviewed set of original debt items. The original primary item remains in the record for compatibility. Historical rules keep their original source scope; the API cannot silently convert them to a different category or add/remove original items. New rules save disabled.

One category includes multiple original invoice items, but creates one charge per company/vehicle/category/month after the strict greater-than-60-day boundary on the first of the month. Exact remaining principal and all original invoice references/dates are retained. Different categories use separate fee items and source keys. Paid principal, existing follow-up fees, written-off debt, unapplied-credit review cases and ambiguous customer responsibility are not guessed into the fee basis. Financing, Work Amount, commissions and investor principal are excluded from logical source configuration.

Monthly aliases recognize both the old original-item source keys and the new logical category keys. Replacing a rule, changing a prospective amount, or disabling/re-enabling an original-item rule cannot produce a second fee for an already-billed category/month. Stored disabled rule definitions preserve the alias mapping without reclassifying old invoices. Activation rejects overlapping active logical/legacy source sets. Configuration and fee generation share the company category lock to avoid simultaneous overlapping rule activation/generation. No historical invoice is changed.

The standard catalogue endpoint reuses the native financial-item creation routine, including automatic unique internal codes, scope/mapping validation and audit. It creates or safely reuses exactly two company-authorized items:

- رسوم متابعة تحصيل سالك / Salik collection follow-up fee.
- رسوم متابعة تحصيل المخالفات المرورية / Traffic fine collection follow-up fee.

The initial monthly amount is 10 AED. Separate company scopes can have their own reviewed definitions without changing another company's item. A conflicting historical named item blocks the entire transaction rather than overwriting it or leaving a half-created pair. Repeating the setup returns the same original IDs. A stale catalogue binding fails closed. Original source items cannot be reused as fee items.

Tax rate, any output-tax account and the reason for its reviewed treatment must be supplied explicitly by an authorized operator. The form starts with an empty rate and never assumes that all service fees are zero-rated or taxable. Catalogue creation creates no invoices, journals, fee rules or activation. An isolated synthetic zero-rate test is not a live tax conclusion.

The existing compliance interface shows the category and source item names, lets a new reviewed rule include multiple source items, locks the economic scope when editing, and keeps value history/effective dates. The native activation approval remains mandatory. The actual browser tested the two-item setup, empty tax default, multiple Salik sources, immutable scope, a 10→12 AED prospective edit and denied activation, in AR/EN desktop/tablet/mobile views.
