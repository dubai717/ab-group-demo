# E47 — corporate accounting evidence and existing cash approval authority (BUILD ONLY)

## Accounting, proposed taxable income and original source

The existing corporate tax draft reported one accounting-profit number and proposed adjustments. It now separately shows net recognized AED income, net expense and their exact profit, while preserving the existing proposed additions/deductions and leaving final taxable income/tax due null. No rate, tax exemption, deductibility, return, filing or company TRN validity is inferred.

`corporate-tax-workpaper.ts` reads the same original posted journal / approved bank entry source, by actual company and selected effective-date period. Account-level debit/credit/net movements expose the classification behind the result. Original and reversing entries remain dated source rows: neither is deleted or silently excluded. Asset, liability, equity, custody and principal movements do not become revenue merely because cash moved. The workpaper follows actual book classification; unresolved legacy misclassification requires review rather than automatic historical reclassification.

Foreign-currency account movements remain separately labelled; their values are not converted into or added to AED profit. A visible review flag prevents a partial AED result from appearing to certify FX/tax completeness. All results state `financialEffect:false`, `filingReady:false`, `sourceCompletenessCertified:false`; registered-period selection is still distinct from final tax approval.

An account or the all-sources action opens the actual original entry register. It reuses the shared financial table, search, typed conditions, paging, row navigation, printing and Excel serializer. Explicit parameters bind every request to the original company, dates and selected account. Server output covers the whole authorized filtered result, not the first page. Source reads are bounded (2,000 account groups / 20,000 detail entries) and fail clearly rather than silently truncate or transfer an unbounded ledger.

Report access uses the original company `ledger_report`; all CSV/Excel/print output additionally requires the existing `ledger_export`, including empty periods. A foreign-company account or technical column injection is rejected. Native bank references and operation links remain hidden without the original company finance/bank-view rights, while accounting debit/credit remain reconcilable. Print/Excel use human localized headers and labels, actual company names and JV/authorized bank references, without UUID columns. No read allocates document numbers or posts anything.

The actual browser caught and resolved two integration defects before saving: the new source action had to use original shared row navigation rather than also opening a generic second record; a retained Arabic kind query must still match the same rows after changing the UI to English. Bilingual canonical search terms now agree with the server's source-kind aliases and preserve the filtered export. Earlier modal/print test readiness failures were corrected in the harness, not labelled accounting defects.

## Existing cash payment approval authority

A newly added before-fix test proved that a synthetic employee owning a normal cash fund, with fund-management/settlement rights but no payment approval, could execute the new cash path. Before any release, the source now additionally requires the existing `ledger_voucher_approve` permission and records the approving actor. The original actual-payment confirmation explicitly covers approval under that authority. The UI hides the cash action without that right. No right or role is automatically granted; a separate explicitly granted synthetic approver succeeds. Bank approval retains its original independent finance approval permission.
