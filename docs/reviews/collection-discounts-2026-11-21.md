# Atomic collection discounts and Owner notification — build only

The existing invoice correction, noncash balanced journal, independent invoice RVs, employee cash custody and notification inbox are reused. An authorized collector with the existing company-scoped `ledger_invoice_correct` right can grant a documented discount while confirming actual cash receipt. No monetary cap or extra prior approval is imposed in this Staging policy; no role or grant is changed. Collectors without that right cannot submit a discount.

The server validates the customer/company/invoice, exact cash plus discount against the remaining balance, nonempty reason and unchanged financial party. The original invoice amount is immutable. Contract schedules, Work Amount and written-off debt remain outside this ordinary collection concession path. Their existing approved correction procedures must be used. Discount-only processing uses the existing native Discount document; this cash action requires a positive actual total and never creates a zero-value RV.

All invoice allocation locks are acquired in a stable order and shared with the native correction path. The discount, its original numbered document and balanced noncash journal, actual RVs, cash custody and notification are one database transaction under the existing idempotency key. A later rejected receipt rolls all of them back. Replaying a request recovers the same result. Concurrent corrections cannot over-credit one invoice. Multi-invoice adjustment confirmation also locks all source invoices before reviewing its immutable preview digest.

Each successful actual Discount (including the original direct correction and grouped Discount procedure) notifies active Owners through the existing inbox in the same transaction, with a unique event key. The authorized notice shows the employee, client file, original invoice, vehicle when present, discount amount, reason and time. No message is sent externally and no task is created. Invoice cancellation and bad-debt write-off are not mislabeled as new discounts. The inbox does not mark a notification read simply by loading the table. Notification details are derived from the original approved adjustment and obey company ledger and customer-read scope.

The existing receivables collection form now separates actual cash, discount and remaining debt. It suggests cash minus the entered discount until the employee manually chooses a partial amount. A failed reason or server check retains the inputs. Only authorized ordinary invoices display the discount inputs. The existing dashboard and communications inbox open the same original notification details.

Acceptance: isolated native tests cover denial without authority, same-key concurrent replay, an unchanged 100 AED invoice with 70 AED actual cash + 20 AED discount leaving 10 AED due, custody of 70 AED only, one Owner notice, direct native notification, full rollback on a later receipt rejection and concurrent discounts capped by the real balance. The real browser confirms 80 AED cash + 20 AED discount, preserves a rejected missing reason, creates one RV and opens the Owner notice with AR/EN desktop/tablet/mobile layouts.

Remaining: full acceptance of other collection methods, future configurable discount limits/approval policy and all master-checklist gaps. This does not activate fees, migrate balances or deploy the package.
