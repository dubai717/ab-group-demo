The collection form displays that same lender caption beside the original invoice. Cash invoices do not acquire invented finance. This does not change a contract, party, invoice, receipt allocation, company or principal/income mapping.

The native contract test verifies the invoice-level caption before collection, rejects an injected financier ID, verifies the original contract caption in the resulting RV/statement and preserves every contract payload. Seventeen combined contract/receivables/discount cases passed. The existing full financial-package browser verifies the caption in the actual collection form in AR/EN with no financier selector, in addition to original statement captions and all existing financial screens. Its isolated fixture explicitly classifies one synthetic original-contract invoice, as the existing native test does; no hosted adoption/reclassification or historical write is executed.

It now waits for the actual source form and opens its direct summary only if the form is hidden, retaining every visibility and data assertion. Original errors are logged before best-effort bounded screenshots. Two repeated fresh fixtures and the full current financial browser passed. No production UI behavior, rate limit or protected gate is loosened.
