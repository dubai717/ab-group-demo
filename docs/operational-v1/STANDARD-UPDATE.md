# مراجعة تحديث ستاندرد الوظيفة

الحفظ يستخدم مسار `security-roles/plan` و`apply` الحالي ومخطط الأدوار القائم، ولا يثبت المخطط أو ينشئ تفويضاً تلقائياً. قائمة تصميم الوظائف لا تتضمن أسماء موظفين؛ تظهر الأسماء فقط في معاينة الأثر عند مراجعة تعديل ستاندرد مرتبط بحسابات فعلية.

المعاينة توضح الصلاحيات القياسية المضافة والمسحوبة، والموظفين المتأثرين، وعدد المنح الفردية المحفوظة لكل منهم. السياسة الحالية `retain_all`: تعديل الستاندرد لا يحذف المنح الفردية أو يغير نطاق الشركات والوحدات.

`individualDenySupported=false` و`individualDenyCount=null` إعلان لحدود التنفيذ، وليس عدّاً صفرياً افتراضياً. المنع الفردي الموروث والإزالة الانتقائية للاستثناءات يحتاجان استكمالاً برمجياً واختبارات حماية. لا يعدان قراراً مالياً مطلوباً من المالك ولا متطلبين مكتملين.

أدلة القبول: اختبار ثانٍ فعلي في `backend/tests/job-standards.test.ts` يربط موظفاً بالستاندرد، ويحفظ منحتيه، ويعاين التغيير دون حفظ، ثم يتحقق من الوراثة الجديدة وبقاء السجلات والنطاق. اختبار المتصفح المستقل يعرض المعاينة الفعلية قبل التأكيد ويحفظ المنحة الفردية عند تحديث الستاندرد.
