# مصدر تقويم الموظف — بناء غير منشور

`backend/src/employee-work-calendar.ts` يستخدم الموظفين وتكليفات الشركات وsettings وسجل HR الأصلي، دون دليل موظفين أو صلاحيات موازية. API العرض والحفظ تحت `/api/personnel/employees/:id/work-calendar` يمر بحراس المصادقة والمعاينة وRLS والطلب الذري الحاليين.

لا ساعات أو أيام دوام افتراضية. يحدد المسؤول الخانات X أو / أو فارغة وساعات اليوم الكامل والنصف والعطلات والاستثناءات صراحة. لا يعتمد النظام جدولاً زمنياً غير مكتمل أو فترات متداخلة أو مقلوبة أو نصف يوم مستخدماً دون ساعات. لا يُعدّ فراغ المصدر جدول إجازة أسبوعية معتمداً.

تسجل النسخ مشفرة مع السبب والمنفذ وتاريخ السريان. لا تُستبدل نسخة أو يعاد تأريخ جدول تاريخي، والتعديل اللاحق بتاريخ سريان أحدث. تُستنتج نهاية النسخة السابقة من بداية التالية عند القراءة، دون تغيير محفوظاتها. تتكرر المحاولة المطابقة دون نسخة جديدة، ويمنع تعارض الإصدار. تستخدم الحسابات نفس مصدر توقيت الإمارات في operational-work-clock.

التعديل يستلزم صلاحية configure الحالية لجميع شركات التكليف الفعلية للموظف، الآن وعند تاريخ السريان المقترح؛ صلاحية شركة واحدة لا تخول تعديل جدول موظف مشترك في شركة أخرى. القراءة تتبع صلاحية ملف الموظف الحالية. لا يتغير راتب أو حضور أو إجازة أو مهمة أو قيد أو صلاحية بسبب حفظ الجدول.

نجحت ثلاث حالات تكامل PostgreSQL حقيقية ببيانات اصطناعية تغطيان التكرار والنسخ والتاريخ والدقة الزمنية والساعات والصلاحيات والتكليف المستقبلي وعدم أثر مالي أو تغيير بيانات العمل، وتعطيل التعديل في معاينة المالك حتى عندما يملك الهدف صلاحية حقيقية.

أضيفت واجهة الجدول من ملف الموظف الأصلي مع اختيار الموقع والشركة من العلاقات الفعلية، وأعمدة موظفين فريدين وصفوف الأيام، والنقر لتدوير X و/ والخانة الفارغة. تعرض 20 عموداً في الصفحة، وتستخدم نفس الحفظ المؤرخ. تجلب API الجماعية الموظفين والجداول والتكليفات بثلاث قراءات مجمعة محدودة، دون طلب مستقل لكل موظف أو polling. المصدر الذي يتجاوز 200 موظف يتطلب تضييق نطاق الشركات.

نجح اختبار متصفح فعلي من زر ملف الموظف: ساعات ناقصة تحفظ المدخلات، وفقد استجابة عملية محفوظة ثم إعادة المحاولة ينتج نسخة واحدة، وفشل قراءة سياق جديد يزيل الخانات القديمة ويتيح المحاولة، مع عرض AR/EN بعروض1440 و768 و390. الصور الاصطناعية المحلية راجعت بصرياً؛ CI يحتفظ بالصور القابلة لإعادة الإنتاج.

المتبقي برمجي: استهلاك الجدول المعتمد في عامل التصعيد وإعادة حساب المواعيد المستقبلية وفق مسار معتمد، وتوسيع قبول تعدد المواقع والأعمدة والقبول المتكامل. الواجهة والمصدر غير منشورين، ولا يدّعي حفظ الجدول وحده اكتمال التصعيد التشغيلي.
