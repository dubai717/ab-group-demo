# Response-review dates in original conversation topics

Unpublished; no hosted installation, external message, financial effect or automatic no-response closure.

The existing topic action now offers an explicit responsible employee and reason. The server requires an active actual HR/account identity, authorized original conversation participation and current legal-company employment/assignment. It reads the employee's original dated work calendar and records a three-working-date **internal review deadline**. The starting UAE date is excluded; subsequent scheduled working dates count, with the final deadline at the last actual shift end. Holidays, split shifts, half days and dated versions use the existing task clock. Missing/conflicting calendars require review instead of assumed office hours. This internal date does not prove delivery or establish a legal customer-response limit.

The original encrypted case/book version, original conversation event/history, audit and internal notifications retain the selected employee, calendar revision, actor, server time, reason and UTC deadline. Existing source authority, session/CSRF, transaction lock, request receipt and revision controls remain. Retry with the same receipt cannot create a second event; stale fresh-key requests conflict. No customer debt, task, grant, invoice or journal is created/settled. Plain waiting or reopening clears the active deadline; old encrypted versions/events remain.

AR/EN uses the existing case forms/readback recovery and employee directory. Authority/locale/page changes suppress stale openings. The date is explicitly displayed as a review deadline with unverified delivery. The provider-free implementation cannot mark a WhatsApp message delivered, send a final customer follow-up or close a topic for no response. Those linked delivery/follow-up proofs and source-calendar/delegation re-evaluation remain engineering work; no-response closure stays false.
