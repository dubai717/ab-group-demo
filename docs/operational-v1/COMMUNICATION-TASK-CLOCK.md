# موعد المتابعة في المحادثة الأصلية

أضيف وقت اختياري بتوقيت الإمارات إلى إجراء ربط المهمة الموجود في المحادثة. يستخدم `ab.tasks` وآلية الساعة الأصلية، ويخزن UTC. التاريخ وحده يبقى دون ساعة مفترضة. اختلاف الوقت عن تاريخ الإمارات يرفض العملية كلها مع خطأ حقل ومرجع، دون مهمة أو إشعار جزئي.

الطلب والساعة في معاملة واحدة؛ المصدر والموظف والتكليف الأصلي لا تتغير. القفل على المصدر وإيصال العملية يحميان التكرار المتزامن وفقد الاستجابة. إعادة طلب لمهمة نشطة سابقة لا تعيد تعيينها أو تغير موعدها؛ الموعد المختلف يحتاج إجراء تعديل الساعة المعتمد. لا اعتماد ذاتي لموعد دقيق إلا وفق الحارس الأصلي للمالك. نطاق الشركة والموظف والمحادثة يتحقق على الخادم.

حد الانتظار لطلب الحفظ45 ثانية؛ الفشل يحتفظ بالمدخلات ومفتاح العملية ويعرض رسالة مفهومة مع مرجع. إعادة المحاولة بعد نجاح الخادم وفقد الرد تعيد المهمة نفسها. تُحدث مهامي بعد الحفظ ولا إرسال خارجي أو أثر مالي.

## سببا التعثر في الواجهة

كانت المحادثة تنتظر تسجيل الاطلاع قبل ربط الأزرار، فتضيع نقرة مبكرة عند تأخر الشبكة. أصبحت الأزرار مرتبطة قبل الطلب، مع منع فتح أكثر من نموذج وتحقيق سياق المستخدم والصفحة واللغة بعد تحميل الموظفين.

وفي ملف الموظف، كان تحميل متزامن يرجع قبل وصول المهام، ويمكن لتهيئة هوية الواجهة المتأخرة تفريغها. الدخول العام للملف والمهمة يهيئ الهوية أولاً وينتظر قراءة المصدر القائمة؛ فشل القراءة لا يفتح ملفاً اعتماداً على حالة قديمة. ما زال تحقق القراءة بعد الحفظ يرفض التحميل المشغول بدلاً من احتساب قراءة بدأت قبل الحفظ كتأكيد له.

النموذج المشترك يضع خطأ الخادم في موضعه المحدد، وليس ملخص التحقق الذي قد يُضاف قبله. أخطاء API ترتبط بالحقل الصحيح، ولا تمسح المدخلات.

## القبول والحدود

نجحت17 حالة خادم مركزة و182 حالة ثابتة وبناء JavaScript و15 رحلة واجهة. شملت الانتظار المصطنع45 ثانية بساعة المتصفح، وفقد نتيجة حفظ ناجح، والطلبات المتزامنة، وتعليق تسجيل الاطلاع، وتحميل المهام المتأخر، والعربية والإنجليزية على1440/768/390. الفواتير والقيود والمنح الأصلية ثابتة.

البيانات كلها اصطناعية. لا مزود WhatsApp أو إرسال أو معالجة مالية. بقية مصادر المهام والرسائل والحالات والتذكيرات والقبول الشامل ما زالت جزئية. هذه حزمة تطوير غير منشورة.
