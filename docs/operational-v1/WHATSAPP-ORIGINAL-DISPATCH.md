# Original message durable dispatch — sandbox only

Reuses original settings for one encrypted technical receipt per original message, plus immutable original customer events/audit. No parallel conversation/task/ledger, schema migration, route, worker, timer, live mode, implicit fetch or environment credentials. Constructor requires explicit sandbox mode, original source pointers and actual human operator; every transaction refuses operating database names and verifies the actual database Owner/work/source authority. It never substitutes an Owner model for an employee.

Before acquiring a new attempt, the original content/contact/review/provider-use-case/consent/window are re-read inside its read-committed write transaction. Original phone rows and message/review/phone-consent locks stabilize the relevant mutable sources; role changes serialize before the actual model is loaded. The caller's payload digest must equal a newly prepared original-source plan. A stale client plan cannot override opt-out, revoked review, changed content/phone, wrong legal company or unreviewed provider configuration. Read-only previews retain their separate consistent snapshot requirement.

Attempt receipt commits before the explicit transport double is called. Concurrent processes/callers find that same receipt and cannot send again. Unknown, failed and process-abandoned attempts never expire into an automatic resend. A private per-instance token can finish only its own acquired attempt; a replacement process cannot adopt it. Exact repeated acknowledgement is harmless, changed terminal outcomes cannot downgrade the original. Provider acceptance means sent, not delivered/read, payment or case completion. Recording the original attempt's outcome after a customer opt-out is allowed without a new send. Loss of acknowledgement storage retains leased/unknown status and blocks resend. If technical state is missing but its immutable attempt remains, dispatch stops for review rather than recreating it.

Original encrypted receipt reads are bounded; secrets/body/phone/private token are not put in audit fields or returned by the lease interface. Malformed provider error numbers retain unknown rather than fabricating a definite failure. Future work includes verified delivery-status reconciliation, human-safe status/review UI, scoped employee/technical acknowledgement authority, approved provider setup/templates, reminders and final acceptance. No live activation or automatic recovery of ambiguous sends.

Acceptance:19 linked native/protocol/source cases passed, including one transport call across concurrent dispatchers, exact acknowledged replay, stale/altered payload refusal, opt-out/review/provider rechecks, timeout/abandoned process, rejected foreign finish, failed acknowledgement persistence, orphan receipt refusal, non-Owner denial, no financial/grant/task changes, and actual local dump/isolated restore comparison of encrypted technical receipts and immutable events. Restoration uses a fresh owned synthetic database only, never the source. This does not prove hosted Auth/Storage restoration or real Meta delivery. TypeScript, provider-free build and189 root/delivery checks passed. All provider responses are explicit local doubles; no real outbound call.
