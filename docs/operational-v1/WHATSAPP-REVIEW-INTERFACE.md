# Original conversation review interface — unpublished and isolated

The existing conversation dialog now offers an inline review panel only with the explicit sandbox review option and an actual active human Owner. Production entrypoint does not set the option. There is no send endpoint/button, token, transport, timer or new conversation system. Existing replies, attachments, cases, tasks and receipts remain intact.

Contacts, language, staff messages/authors, consent, content review and dispatch states are read from their original sources. Phone/message/review choices start blank. Marketing preference is not messaging consent. Consent purposes are independent, while channel refusal/withdrawal applies to the same phone across profiles. The current language comes from the customer, not nationality.

Writes retain their body and idempotency key after an unknown response. Once a write is acknowledged, retry performs exact-receipt readback only. The exact original immutable receipt is checked separately from current consent/review state. Navigation is guarded and entered values remain on failure. Source changes require rereading; cached request success cannot bypass current authority, changed phone/content or reactivate old consent. Dispatch states distinguish leased/unknown, provider acceptance and refusal; no state is a payment or delivery receipt.

The suite now includes this independent fixture.
