# Official WhatsApp media — inactive bounded read seam

`backend/src/whatsapp-media-boundary.ts` adds a sandbox-only media reader for the existing official ingress pipeline. It is not registered in the application, has no global fetch/environment access, does not create attachments or approve documents, and sends no messages. The caller must explicitly supply an injected transport, token, phone number, pinned Graph version, allowlisted **test** media IDs and byte budget. No provider version, phone, consent, price or live account is selected by the implementation.

Metadata is requested only from the fixed Graph origin with the bound phone_number_id. Before a file read, the returned media identity, supported MIME, positive exact size and canonical SHA256 value must match. Only the explicit HTTPS official lookaside attachment path is accepted: foreign hosts, user information, alternate ports, fragments and other paths refuse. Both reads reject redirects and have deadlines. Metadata is capped at16KiB; files at the explicitly configured maximum, at most8MiB. Declared lengths and streamed bytes are bounded, and rejected streams are cancelled. The exact downloaded size, response MIME and SHA256 are checked before bytes can reach an attachment adapter. No automatic retry or repeated background polling is added.

The returned file remains **unscanned and unapproved**. The original file validator/scanner, encrypted store, message/source authorization, original attachment download authorization and immutable event linkage still have to be integrated and independently accepted. PDF/JPEG/PNG are supported at this seam; audio/video/sticker/other types are explicitly unsupported rather than silently treated as files. A correct MIME/checksum is not malware scanning or documentary verification.

Seven offline tests cover valid exact bytes, no-request disabled/foreign binding behavior, hostile URLs, metadata mismatch, size/type/checksum/length mismatch, stream cancellation and provider/network failures without retries. All use injected synthetic Response objects; **no external provider call or real attachment download occurred**. TypeScript passes. This is partial unpublished engineering, not an operational integration or live provider acceptance. Provider/number/templates/consent decisions and original store/inbox/outbound integration remain outstanding.
