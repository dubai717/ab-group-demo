# Bounded original Storage reads

The original Supabase ObjectStore now bounds ordinary downloads as well as optional recovery reads. Previously ordinary `get` buffered the complete response with arrayBuffer; its integrity check could run only after that transfer. The existing business-file ceiling is now20MiB of encrypted bytes. Callers may supply a stricter bound; invalid limits fail before a request. Customer, vehicle, personnel/linked-login and general-message reads derive a small compatible encrypted-envelope bound from the stored plaintext size; exact-file recovery uses the validated upload length.

Declared oversized/malformed Content-Length cancels before buffering. Chunked or underdeclared streams are counted and cancelled when actual bytes exceed the bound. Content-Length is not itself treated as evidence of file integrity; canonical decoded bytes, stored size and SHA256 are still verified by the original shared recovery helper. The original AES-GCM envelope and all historical IDs/paths are unchanged. The same helper covers older valid personnel/communication/customer/vehicle uploads. Ordinary successful uploads still need no recovery read. No polling, permission change, public cache or implicit retry is introduced.

Original Storage GET/optional GET/POST now explicitly reject redirects. A real local two-origin test proves private headers and uploaded bytes cannot follow a307 to another origin. Object paths, original private apikey semantics, create-only x-upsert=false and error handling otherwise remain. The independent backup adapter retains its own separate reviewed50MiB archive path/transport; no operating backup was downloaded or altered.

Seventeen linked provider/recovery/unit cases pass, including declared/streamed limits, no-request invalid limits, only404-as-absent, authorization/quota errors, original envelopes through10MiB and redirect refusal. Four linked native original customer/vehicle/personnel/HTTP400/message cases pass. TypeScript, provider-free build and189 root/deployment regressions pass. Test transports and endpoints are synthetic/loopback only. This does not attribute or measure the historical Supabase86.58GB, and no live Egress saving is claimed without deployment and measurement.
