# Physical operating centres — work in progress, review only

Original sources were inspected again: `ab.areas` / `ab.emirates` are geography, `ab.departments` / HR departments are administrative units, financial cost-centre definitions classify accounting, and `business-centers.js` groups existing screens. None provides the actual operating-centre/company directory requested for work scope. Reusing their identities as physical centres would fabricate relationships.

`backend/review/operating-centres.sql` is an unregistered review candidate, not a hosted migration or an enabled runtime source. It introduces dated, append-only physical-centre snapshots with original tenant/user/emirate/area foreign keys and explicit company links. Multiple companies and genuinely separate company/centre mappings are supported without assuming a company's legal domicile equals its work location. New snapshots retain older links and effective dates. They do not grant rights, change user company/department memberships, move balances or reclassify historical financial records.

Runtime source reads/inserts are restricted to active Owner with tenant RLS; update/delete privileges are absent. Version/parent/date continuity is serialized. Link inserts belong to the same transaction as their snapshot, preventing later attachment to an old version. Source actor identity is checked and recorded time is server-controlled. The application must still add strict readiness checks against bypass/incomplete policies before any writer is enabled.

One direct isolated SQL integration case verifies actual Owner/non-Owner behavior, withheld other-user reads, absent update/delete, unchanged memberships/grants/GL, attempted late link insertion, retained original two-company snapshot and one winning concurrent revision. An initial denial assertion exposed trigger validation preceding RLS: explicit Owner authorization was added before source validation; the assertion was retained. This is not full directory/API/UI acceptance, a hosted migration, a restore test or effective geographic authorization.

Remaining engineering: source readiness/tamper checks; original Owner permission-screen directory editor with names and original company options; reasoned fresh impact review, idempotent apply/readback and immutable audit; dated source selection and unresolved mapping handling; explicit scope selection separate from primary work location and original role authority; safe preview of affected users; actual API/DB enforcement and AR/EN E2E. No inferred centre data or automatic grants. No new role or parallel permission engine.

Do not add this file to automatic manifests or install it on a hosted database during build. No real mappings have been recorded and no approval is requested for this unfinished candidate.
