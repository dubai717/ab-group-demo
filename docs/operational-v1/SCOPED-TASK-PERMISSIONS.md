# Scoped task additions, denials and recovery — unpublished

Extends the existing grant/standard/denial engine; no parallel permission system. Legacy task view/create/assign/status permissions are now independently grantable within group/company scope. Task grants are explicitly excluded from user-profile visibility and cannot become HR/financial access. Controllers resolve each original company, current role/grants, assignment and work access. The current session's navigation projection can show an individually granted task section without changing its job standard.

Explicit view denial applies to original task list/history/action and MyWork rows/counts/employee inspection. Status denial rejects start/submit, including an identical cached request. Assignment and operational review are separate: a new scoped assignment addition alone does not approve completion or a deadline. Original built-in role/hierarchy review remains compatible. Financial source conditions remain in their existing controllers.

A narrow `task_review` action uses the same original role/grant engine and an uninstalled additive `task-review-permission.sql` candidate. It adds only a catalog entry, grants nobody and changes no balance. The runtime reads actual catalog readiness; the employee permission UI and grant/plan routes withhold the new action until defined. Existing broad HR management is not relabeled as a narrow approval checkbox. An explicit denial of the new review action also narrows compatible review paths. No hosted schema was applied.

Manual task company/employee choices use a bounded, on-demand, read-only repeatable original-source adapter. It verifies the actual database actor/role/work context, filters exact authorized companies and actual dated employee assignments, returns names only and refuses an Owner-shaped employee model. View-only users trigger no assignee inventory. The original HR capabilities/profile/library APIs do not acquire new reads or grants. Company selection starts blank, changing it preserves other input and clears the assignee, and Arabic names use the existing localized fields.

The original UI consumes per-row action flags. History remains available to an authorized reader; hidden Open buttons still use the existing shared row/keyboard adapter. There is no new table/navigation system. New task saves retain the same key/body after an unknown reply. After a known acknowledgement, failed readback retains a locked form and retries reads only; successful verification displays the original task number, closes the form and invalidates the original MyWork source. Tasks assigned to a colleague stay outside the creator's default own bucket.

Task creation/action/clock cached recovery rechecks current rights and the original saved source before returning old success. Permission mutations serialize with the existing authority snapshot; identical retries serialize through the original request receipt. Recovery never reruns an acknowledged action. No role standard, financial approval, journal, receipt or invoice is changed by task authorization.
