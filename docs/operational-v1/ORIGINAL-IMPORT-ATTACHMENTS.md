It is not a client field, role, permission or replacement import engine. The reference binds actual tenant/operator, company, existing import record/hash/confirmed preview, exact source row/file index, expected existing target and file name/type/digest. Its immutable in-process reference cannot be reconstructed from JSON. It retains no source packet or Owner model between requests.

For an existing target the source target ID must match. For a newly generated customer/vehicle ID, a bounded original-table lookup proves that exact target was created by this actual actor in this same transaction/company. The retained file identity uses the original import/preview/row/file instead of the newly randomized, rolled-back target ID. Original authorization, source mapping, required fields, duplicate decisions, row locks, validator, scanner and upload/version writer remain in force. Sources lacking retained-object reads preserve their original legacy storage fallback; recovery is not falsely promised there.

A whole-batch rollback may retain only its already encrypted external object. Retrying the same reviewed source with the recoverable original adapter verifies/adopts the exact path/ciphertext and creates one target/file. A remapped source or changed actor/target/body cannot reuse that identity. The original file-added history retains a small encrypted import provenance reference without publishing the preview token or source file bytes. No extra completed task, second ledger or approval is created. The implementation reuses the loop's already loaded source; it does not reread the full import packet for each attachment.
