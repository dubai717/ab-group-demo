# Original dated centre import — unpublished, disabled by default

CSV/XLSX centre import reuses `planOperatingCentre` and `applyOperatingCentre`; it does not create another organization, cost-centre or permission system. Existing source readiness/signature guards must pass first. No centre schema is initialized automatically. Source reference, names, recorded geography, actual company references, effective date and reason are validated against the original planner. Preview is an uncached repeatable-read/read-only transaction. Heavy source planning is bounded to25 rows per file, not an unbounded catalog scan.

A stable tenant/source-reference derived internal UUID prevents a second centre when the same file/reference is retried. It is not a visible business code or an automatic identity merge. Existing identity or potential matching names/geography remain review rows; existing centres/history/future versions are never overwritten by the batch. Explicit valid-only confirmation can skip unresolved rows. The original writer retains immutable dated versions, actual company links and encrypted before/after audit; the batch also retains bounded encrypted row/source-reference provenance. Creating a centre never assigns users, changes legal employers or grants company/region access.

`centreImportEnabled` defaults false and is not enabled by the runtime server. The source can be previewed only when its separately reviewed schema is present; only the owned synthetic fixture enables batch apply. Apply checks current Owner/work authority before original receipt recovery, serializes security/company/centre directory snapshots, revalidates the signed plan and commits all original versions/links/audit/receipt together. The existing manual centre writer joins the directory lock. Same-key retry recovers; different keys cannot reuse a consumed plan. A second-row audit failure rolls back the whole batch.

The original centre source viewer offers the shared importer, hides/restores its parent and reloads the original latest source with bounded GETs after acknowledgement. Future dated records are visible as latest recorded versions, not falsely shown as currently effective. The original employee permission draft remains intact. Parent selection is part of the importer context: an obsolete held preview is removed after choosing another employee. No reply can mutate the new employee frame. Existing company/employee/customer/vehicle importers retain their original paths.
