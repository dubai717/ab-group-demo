# Original personnel document import — unpublished, disabled by default

The existing shared importer now previews CSV/XLSX metadata plus a ZIP of files for existing employee numbers. It never creates an employee, login account or financial entry. An optional company ID is only a consistency check against the original legal employer; it cannot move the employee or file. An explicit filename matches the ZIP path without fuzzy matching. The original strict parser, bounded archive/attachment helpers and personnel ownership/upload validator are reused.

The original personnel document writer now exposes an internal validation/write seam; all original routes still use that same writer. Apply calls it in the existing transaction and uses the original scanner, document versions, HR records, text indexing and per-employee audit. New files remain Submitted even after a clean security scan; scanning is not legal verification. Each original document_added audit includes its source/ZIP hashes, source row and batch request key, encrypted in the original employee/company audit context. No additional audit action inflates document/task counts. No approval or historical correction is performed.

Preview is READ ONLY / REPEATABLE READ, uncached and bounded to25 rows. Apply is limited to five valid new documents per transaction, using explicit confirmation and explicit valid-only skipping. Unmatched ZIP files block apply. The original import/security/company/personnel locks and fresh actual-Owner/work checks run before cached receipt recovery. The new employeeDocumentImportEnabled option defaults false and the runtime server does not enable it. A recoverable create-only object provider is also required. No migration or automatic import job is installed.

Duplicate checks read only requested employee/kind/content-hash combinations, with grouped counts, rather than loading historical attachment rows. They use actual document ownership, flag inconsistent/missing HR ownership records and detect originals in a linked login account. Linked originals retain their user ownership and logical links; import does not clone, move or repair them. Protected investor-evidence originals are not routed through this HR adapter. Unrelated different-content history does not invalidate a new-only preview; relevant duplicate/employee/company changes do. No ordinary employee can probe this Owner-only source.

Database metadata, audit, index and receipt changes roll back together. Already uploaded encrypted objects cannot participate in that PostgreSQL rollback; exact same-context/request retries reuse their validated paths/bytes without overwrite or deletion. Unknown outcomes freeze the same body/key. Definite rollback errors allow correction while retaining the request key for safe unchanged-file reuse. Historic orphan cleanup is not performed. Parent-version renewal import remains unsupported; original manual version creation stays available.

The shared Arabic/English dialog retains CSV/ZIP files, displays row/field diagnostics, exposes the existing employee name/number and never treats saving as document approval. Acknowledged readback failure retries bounded original GETs without another POST. Register filters are retained. An open original personnel edit form blocks opening import without discarding its inputs. Long headings wrap on mobile.

Evidence:13 linked native tests passed across this importer, original company/employee imports and Owner View As. Cases include CSV/XLSX, required/invalid/photo/company fields, unsafe/unmatched ZIP, batch cap, default-off and worker denial, same/different-key concurrency, stale employee source, independent unrelated history, linked original preservation, inconsistent legacy relation review, original scan rejection, late audit rollback, retained encrypted-file retry, immutable-source provenance and unchanged employee/user/grant/journal facts. Focused actual browser flows passed in Arabic/English1440/768/390, including unknown employee diagnosis, retained inputs, lost committed response, same-body/key recovery, acknowledged GET-only retry, original bytes and Submitted state. TypeScript, build and root/full-suite results are tracked separately in BUILD-STATE. No real import or hosted data change occurred.

Remaining: explicit parent-version renewal/broader document-owner imports, remaining organization/opening-balance mapping and approved reconciliation, full source-scope and integrated release acceptance. This feature does not complete the grouped import or document requirement.
