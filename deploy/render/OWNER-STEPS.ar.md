# الخطوة الحالية: حساب مجاني فقط — لا إنشاء خدمة ولا نشر

فرع الإعداد: **staging/ab-group-test**، من أحدث فرع تطوير مركزي، وليس main القديم. PR #10 و#11 والفروع السابقة محفوظة دون دمج/إغلاق. ملفات Render لا تنشئ مورداً بمجرد رفعها إلى GitHub؛ لكن الضغط على Create Web Service أو Apply Blueprint قد يبدأ الفوترة وأول نشر فوراً حتى لو Auto Deploy=Off. لا تضغط أيّاً منهما قبل الموافقة المنفصلة.

## المطلوب من المالك الآن

1. افتح https://dashboard.render.com وسجّل حساباً مجانياً. أبقِ Workspace بالخطة المجانية إن كانت متاحة. لا تشترِ خطة Workspace ولا تضف بطاقة/تفعّل خدمة مدفوعة الآن.
2. يمكنك ربط GitHub مع منح تطبيق Render وصولاً إلى المستودع dubai717/ab-group-demo فقط. إذا عرضت العملية زر إنشاء/نشر، توقف قبله. لا حاجة إلى أسرار أو ZIP أو PowerShell في هذه الخطوة.
3. أخبرني بأن الحساب جاهز. إذا كانت شاشة Render تعرض تقديراً مختلفاً، أعطني أسماء البنود والمبالغ فقط (دون بطاقة أو أسرار). نراجع تكلفة Starter قبل السماح بإنشاء الخدمة وأول نشر.

## التكلفة المقترحة قبل الاشتراك

- Web Service واحدة، نسخة واحدة، Starter / 0.5c-512mb: المستهدف USD 7 شهرياً، قبل الضرائب والاستخدام الزائد، وفق قائمة Render الحالية. لا نفترض أن عبارة Starter تعني Workspace مدفوعة؛ المقصود حوسبة خدمة الويب.
- Workspace مجاني: USD 0 إذا أكدت شاشة حسابك ذلك. لا مقاعد/إضافات مدفوعة.
- Supabase الحالية Free وbucket الحالي: USD 0 ضمن حدودها. لا Render Postgres أو Redis أو Persistent Disk أو Cron أو نطاق مدفوع.
- رابط onrender.com وTLS من المنصة؛ الاسم النهائي يتحدد بعد حجز الخدمة، وليس رابطاً نشطاً الآن.
- النسخ الاحتياطية المجدولة والتخزين الخارجي غير مفعّلين؛ تكلفتهما النهائية تعتمد على الوجهة/الجدولة التي ستوافق عليها. لا تُحتسب تكلفة مجهولة على أنها صفر مضمون. أي ضرائب/تجاوزات تخضع للفوترة الفعلية. تأكيد المبلغ النهائي يكون من ملخص Render قبل الالتزام؛ لم تُشترَ خدمة.
- Free قد تتوقف عند الخمول؛ لا ضمان تشغيل متواصل لقاعدة Supabase Free. لا ترقية تلقائية أو طلب keep-alive للتحايل على قيودها.

## بعد موافقة منفصلة على الدفع وأول نشر فقط

- أنشئ Web Service واحدة من المستودع وفرع staging/ab-group-test، Root Directory فارغ (جذر المستودع)، Node 24، Starter، instance=1، Auto Deploy=Off، health=/api/health. ملفات render.yaml جاهزة للمراجعة، وليس للتطبيق الآن. اختيار المنطقة الأقرب إلى Supabase متاح أثناء إنشاء الخدمة، ولا يغيّر منطقة قاعدة البيانات.
- Build: `npm ci --ignore-scripts --include=dev --omit=optional --no-audit --no-fund && node backend/deploy/build.mjs`
- Start: `node backend-build/deploy/server.js`؛ لا تستخدم npm start لأنه ما زال يشغّل العرض التجريبي القديم. Build/start لا ينفذان migrations أو provisioning.
- في مخزن أسرار Render فقط: DATABASE_URL الحالية للدور ab_runtime، DATA_ENCRYPTION_KEY الأصلية، SUPABASE_URL، SUPABASE_PUBLISHABLE_KEY، SUPABASE_SECRET_KEY. GitHub لا يتيح قراءة القيم المحفوظة؛ يُدخل المالك النسخ الأصلية المحمية مرة واحدة، دون المحادثة أو ملفات المستودع. لا تُدخل MIGRATION_DATABASE_URL أو مفاتيح scanner في خدمة الويب.
- الإعدادات غير السرية: APP_ENV=staging، NODE_ENV=production، SUPABASE_BUCKET=ab-private-test، NODE_EXTRA_CA_CERTS=./backend/certificates/supabase-prod-ca-2021.crt، PUBLIC_ORIGIN=https://اسم-الخدمة.onrender.com **دون /** في النهاية. PORT تحدده Render. HTTPS من Render، وSecure/HttpOnly session cookies من Backend. الواجهة لا تتلقى أي مفاتيح.
- الخدمة تقدم الواجهة وAPI من الأصل نفسه. لا تعديل ألوان/شعار/لغات/صلاحيات. المرفقات تبقى محجورة دون فاحص حقيقي.
- يلزم حساب دخول وهمي محدد للمتصفح؛ حسابات CI السابقة كلمات مرورها لم تُنشر ولا نفترض إمكانية استعادتها. بعد وجود الخدمة نجهز إنشاء حساب وهمي مع حفظ كلمة مروره في مخزن أسرار المالك، دون تعديل أي حساب قديم أو طباعتها في السجلات.

## التحديثات بعد الاختبارات — معطّلة حالياً

staging-ci.yml يعمل بلا أسرار سحابية: build، حفظ سلوك النسخة، PostgreSQL محلي وهمي، صلاحيات/RLS وbackup/restore معزول، متصفح كمبيوتر/هاتف/لغتين، وبناء الصورة المحمولة. لا تنشر خطوة منه شيئاً. النشر المستقبلي يحتاج موافقة تفعيل قالب render-staging-deploy.yml.example، وحفظ Deploy Hook في GitHub Environment render-staging مع حماية المراجعة في البداية. النشر يشترط نجاح job الاختبارات المستدعى في workflow نفسه لا skipped/cancelled، وpush للفرع الموثوق نفسه؛ لا ينفذ كود PR في job المميز، ويرسل SHA المختبر نفسه إلى Render. Auto Deploy يبقى Off حتى لا يتجاوز هذه البوابة. لا migration تلقائي.

بعد أول نشر: نفحص HTTPS وCookie/CSRF وعدم تعرض ملفات الأسرار، الدخول، إنشاء/تعديل/استرجاع شركة وحسابين وبـManager، الصلاحيات والمرفقات على الكمبيوتر والهاتف؛ عند الفشل نوقف الترقية ونرجع لكود معروف دون rollback تلقائي للجداول. main والإنتاج يظلان مشروطين بموافقة منفصلة دائماً. لا تفعّل hooks أو ترفع قيود المراجعة لمجرد نجاح اختبار محلي.
